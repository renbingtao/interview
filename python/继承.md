# 继承

Python 支持**多继承**，查找顺序遵循 **MRO（Method Resolution Order，方法解析顺序）**，C3 线性化算法

## 基础语法

```python
class A:
    def hello(self):
        print("A hello")

class B:
    def hello(self):
        print("B hello")

# 同时继承 A、B
class C(A, B):
    pass

c = C()
c.hello()               # 先找A的hello，A有就用A，不再找B
print(C.__mro__)        # 查看查找顺序：C -> A -> B -> object
```

语法：`class 子类(父1, 父2, 父3...):`

查找规则：**从左往右，沿着 MRO 链依次查找，找到第一个匹配名字就停止**。

## MRO：C3 算法

Python3 全部使用 **C3 linearization（C3 线性化）** 生成 MRO 列表。

> 一句话：保证两个原则
>
> 1. 子类一定出现在父类前面
> 2. 父类的继承顺序，保持原有相对顺序（单调性）

## 菱形继承（钻石继承）

```text
    Base
   /    \
  X      Y
   \    /
    Z
```

```python
class Base:
    def func(self):
        print("Base")

class X(Base):
    def func(self):
        print("X")

class Y(Base):
    def func(self):
        print("Y")

class Z(X, Y):
    pass

z = Z()
z.func()
print(Z.__mro__)    # Z → X → Y → Base → object
```

C3 会自动排好顺序，**不会重复多次进入 Base**（这就是 C3 解决了老式深度优先的弊病）。

## super () 在多继承里

⚠️ 关键：**super () ≠ 直接找父类！**

`super()` 拿到的是 MRO 链里**下一个类**，不是代码上写的父类。

```python
class Base:
    def __init__(self):
        print("Base init")

class X(Base):
    def __init__(self):
        super().__init__()
        print("X init")

class Y(Base):
    def __init__(self):
        super().__init__()
        print("Y init")

class Z(X, Y):
    def __init__(self):
        super().__init__()
        print("Z init")

z = Z()
print(Z.__mro__)
```

执行顺序：

`Z.__init__` → super 到 X → X 里 super 到 Y → Y 里 super 到 Base → Base 执行完回到 Y，再回到 X，再回到 Z。

👉 Base **只会被调用一次**，不是两次！

## 成员查找规则（属性、方法通用）

调用 `obj.name`：

1. 先在实例自己的 `__dict__` 找
2. 找不到，沿着这个实例所属类的 **MRO 列表顺序** 依次去每个类的 `__dict__` 查找
3. 找到第一个就返回；走完 MRO 还没有 → AttributeError

> 注意：类属性、普通方法、`__xxx` name mangling 后的成员，全部遵循 MRO 查找。

## 工程最常用模式：Mixin（混入类）

**Mixin 是 Python 多继承最佳实践，强烈推荐**

规则：

- Mixin 只提供附加功能，不单独实例化
- 不继承业务主类，一般只继承 object
- 主类放前面，Mixin 放后面：`class MyClass(业务主类, Mixin1, Mixin2)`

示例：

```python
class LogMixin:
    def log(self, msg):
        print(f"[LOG] {msg}")

class SaveMixin:
    def save(self):
        print("保存数据")

class User(SaveMixin, LogMixin):
    def __init__(self, name):
        self.name = name

u = User("tom")
u.log("hello")
u.save()
```

Mixin 就是用来 “混入” 额外能力，**而不是用来表达 is-a 关系**。

## 最佳实践

1. **优先组合，其次 Mixin，尽量避免复杂菱形继承**
   组合：`self.xxx = OtherClass()` 是最稳的，没有 MRO 问题。
2. 多继承尽量扁平化，不要搞很深的继承链
3. 所有参与协作的类，构造统一用 `super().__init__()`，不要混用硬编码父类调用
4. 如果父类构造有参数，所有中间类都要兼容参数（协作继承参数坑很多）

```python
# 坑示例：参数对不上直接报错
class A:
    def __init__(self, x):
        pass
```

5. 顺序很重要：`C(A,B)` 和 `C(B,A)` 是两套完全不同的 MRO！
6. 不要用多继承去模拟 Java 接口；鸭子类型 + ABC 抽象基类更适合做契约
7. 写复杂多继承时，随时打印 `__mro__` 看顺序
