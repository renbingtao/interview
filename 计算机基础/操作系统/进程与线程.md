# 第2章 进程与线程

## 2.1 进程与线程简介

### 2.1.1 进程的概念和特征

为了使每个程序能独立运行，必须为其配置一个专门的数据结构，称为 **进程控制块**，PCB
操作系统通过PCB记录进程的基本信息和运行状态，从而实现对其的控制与管理
**程序段**、**数据段**、**PCB** 三者共同构成进程实体，也叫进程映像。其中PCB是最核心的部分
创建进程的本质使创建其PCB，相应地，撤销进程即释放该PCB及相关资源

- 进程的定义：进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位
- 进程的特征：动态性、并发性、独立性、异步性

### 2.1.2 进程的组成

#### PCB

PCB常驻内存，是进程存在的唯一标志，系统唯有通过它才能感知并管理进程
在进程的整个生命周期内，系统始终依赖PCB对其进行管理：
操作系统准备调度某个进程运行时，从PCB中读取当前状态、优先级等；若该进程被选中，系统根据PCB中保存的CPU上下文恢复执行现场，并根据记录的内存地址找到对应的程序段和数据段
当进程被暂停时，其当前的CPU状态会被保存回PCB
当进程正常结束或强制终止时，系统将回收PCB

PCB通常包含的内容

1. 进程表示信息
   - 进程ID（PID）、父进程ID（PPID）、用户ID（UID）
2. 进程调度信息
   - 进程当前状态、进程优先级、CPU占用时间等
3. 资源和内存信息
   - 代码段、数据段、堆栈段在内存中的起始地址，已打开文件的描述符列表，占用的IO资源
4. 处理机状态信息
   - 也称CPU上下文，包括各种寄存器的值，如通用寄存器，程序计数器，栈指针，程序状态字等
   - 进程被切换出CPU时，保存到PCB；被调度运行时，恢复至CPU

操作系统通常有两种方式组织PCB：链接方式和索引方式

- 链接方式：系统将处于相同状态的PCB通过指针链接成一个队列，比如就绪队列、阻塞队列。对于阻塞队列，还可根据其阻塞原因划分为多个阻塞子队列
- 索引方式：系统为每种状态建立一个索引表（如就绪索引表、阻塞索引表），表项指向对应状态的PCB

#### 程序段

程序段是进程中可被CPU执行的代码部分
程序本身是静态的，可被多个进程共享

#### 数据段

包含进程运行所需的各种数据。每个进程的数据段是私有的

### 2.1.3 进程的内存映像

程序被加载时，OS会为其建立一个有明确上下界的虚拟地址空间，该空间的逻辑布局称为 **进程的内存映像**。它反映了进程在运行时代码、数据、堆、栈等部分的组织方式。主要由以下几个区域构成

1. 代码段
   - 存放程序的机器指令，即编译后的可执行代码。该代码通常是只读的，包含
   - .init:程序启动时由OS自动调用的初始化代码
   - .text:存放主程序的指令。如main()编译后的机器指令
   - .rodata:存放只读数据，如字符串常量"hello world"
2. 数据段
   - 用于存放全局变量和静态变量(static变量)，可分为
   - .data:存放已初始化的全局变量和静态变量
   - .bss:存放未初始化的全局变量和静态变量
3. PCB
   - PCB不属于进程的虚拟地址空间，它由OS内核维护，存放在系统内核中，对用户进程不可见
4. 堆
   - 程序运行时动态申请内存的区域。堆从低地址向高地址增长，大小不固定
5. 栈
   - 存放局部变量，函数参数，返回地址等信息。由系统自动管理，遵循后进先出，从高地址向低地址扩展
6. 共享库的存储映射区
   - 共享库用于提供进程所依赖的公共函数代码。代码是只读的，且被多个进程共享

代码段和数据段的大小在程序加载时就已确定，而堆和栈则可动态扩展和收缩
一个典型进程在内存中的映像如下：

```
操作系统内核区     用户代码不可见区
栈
⬇
⬆
共享库的存储映射区
⬆
堆
读写数据段.data  .bss
只读代码段.init  .text   .rodata
```

### 2.1.4 进程的状态与转换

进程具有五种状态，其中前三种是基本状态：

1. 运行态：进程正在cpu上运行
2. 就绪态：进程已获得除CPU以外的所有必要资源，一旦获得CPU，便可立即投入运行。系统中可能有多个就绪进程，通常将它们组织成一个 **就绪队列**
3. 阻塞态：也称等待态。进程因等待某一个事件而暂停运行。即使CPU空闲，也无法执行。同理，系统组织成 **阻塞队列**
4. 创建态：进程正处于创建过程中，尚未进入就绪态。创建过程包含多个步骤：
   - 先申请一个空白的PCB，写入用于控制和管理进程的信息
   - 分配运行时所需的资源，如内存
   - 所有资源已到位，转为就绪态，插入就绪队列
5. 终止态：进程已完成执行，等待系统回收资源。此时不参与调度，但PCB等信息会暂时保留，直到完成清理

进程状态的转换

- 就绪态 -> 运行态：处于就绪态的进程被调度程序选中，获得CPU的使用权，转换为运行态
- 运行态 -> 就绪态：处于运行态的进程在时间片用完后，必须主动让出CPU，从而转回就绪态。在可剥夺式调度系统中，若有更高优先级的进程就绪，则当前进程也会切换回就绪态
- 运行态 -> 阻塞态：运行中的进程通过系统调用请求某项服务（如IO操作），而该请求无法立即满足，进程便会主动进入阻塞态。并非所有系统调用都会导致阻塞，只有那些需要等待外部事件的操作才会引发状态转换
- 阻塞态 -> 就绪态：当进程所等待的事件发生时（如IO操作完成），相应的中断处理程序回将其状态由阻塞态修改为就绪态，并重新插入就绪队列

进程从运行态变成阻塞态是主动行为，而从阻塞态变成就绪态是被动行为

### 2.1.5 进程控制

进程控制的操作包括：创建新进程、撤销已有进程、实现进程状态转换等操作
在操作系统中，这些控制操作通常以 **原语** 的形式实现。原语在执行期间不允许被中断，是一个不可分割的基本单位，确保了关键操作的原子性和一致性

#### 进程的创建

一个进程可以创建另一个进程。创建者称为 **父进程**，被创建的进程称为 **子进程**。子进程在创建时会复制父进程的当前状态，包括：程序代码、数据段、堆栈内容、打开的文件描述符、环境变量等
子进程与父进程时互相独立的实体，拥有各自的PCB和虚拟地址空间
以下行为都会创建进程：终端用户登录系统、作业调度启动批处理任务、系统提供服务、用户程序发起应用请求
操作系统通过 **创建原语** 建立新进程，过程如下

1. 分配唯一标识并申请PCB：为新进程分配唯一的进程标识号PID，从系统PCB池中申请一个空白PCB。若PCB资源耗尽，则创建失败
2. 分配新进程运行所需的资源：如内存、文件、IO设备等。这些资源可以从OS获得，也可以从父进程继承
3. 初始化PCB：初始化的内容包括：标识信息、处理机状态信息、调度与控制信息和内存与资源信息。通常将新进程设置为最低优先级
4. 插入就绪队列：若系统允许新进程参与调度，则将其PCB插入就绪队列，等待调度

#### 进程的终止

以下事件可引起进程终止：

- 正常结束：进程完成任务后主动退出
- 异常结束：进程在运行过程中发生严重错误，导致无法继续执行。比如：存储区越界、非法指令、特权指令违规、算术运算错误、IO故障、运行超时等
- 外界干预：如操作员强制终止、OS因资源不足或安全策略终止进程、父进程通过系统调用终止子进程

OS通过 **终止原语** 完成进程的撤销，步骤如下：

1. 根据被终止进程的PID，检索PCB，读取当前状态
2. 若进程处于运行态，立即剥夺CPU，并触发调度程序选择下一个就绪进程
3. 释放该进程占用的所有系统资源，统一归还给OS
4. 若系统支持 **级联终止**，则递归终止其所有子孙进程；否则，子孙进程继续执行
5. 将该进程的PCB从所在队列或链表中移除，完成清理

并非所有所有OS都会采用级联终止策略。比如linux，父进程终止时，子进程不会自动终止，而是由init进程（PID=1）收养

#### 进程的阻塞和唤醒

当一个正在运行的进程因等待某个外部事件而暂时无法继续执行时，会主动调用 **阻塞原语** Block，从而使自己从运行态转换为阻塞态。常见事件包括：请求系统资源暂时不可用、等待IO操作、等待接收数据、等待信号量等
阻塞是进程的主动行为，因此只有处于运行态的进程才能执行阻塞操作。阻塞原语的执行过程如下：

1. 保存当前进程的CPU现场（如PC、PSW）到PCB中
2. 将其PCB中的状态字段修改为阻塞态，并将该PCB插入所等待事件的等待队列中
3. 调用调度程序，从就绪队列中选择另一个进程投入运行，以释放CPU资源

当被阻塞进程所等待的事件发生时（如IO操作完成、所需数据到达），由内核的中断处理程序或合作进程调用 **唤醒原语** Wakeup，将该进程重新激活。唤醒原语的执行过程如下

1. 在指定事件的等待队列中找到目标进程的PCB
2. 将其从等待队列中移出，并将状态置为就绪态
3. 将该PCB插入就绪队列，等待调度程序选中并恢复执行

阻塞与唤醒是一对作用相反的原语，必须成对使用。若调用了阻塞但没有调用唤醒，则该进程将永久停留在阻塞态

### 2.1.6 进程的通信

进程通信（IPC，Inter-Process Communication）是指进程之间的信息交换。可分为低级通信和高级通信

- 低级通信：主要用于传递控制信息，如同步、互斥，典型代表是PV操作
- 高级通信：用于高效传输大量数据，主要包括共享存储、消息传递和管道通信、信号等

#### 共享存储

进程的地址空间通常是互相隔离的。OS提供了共享存储机制，通过特殊的系统调用，创建一段独立的内存区域，将其映射到多个进程的虚拟地址空间中，这些进程都能直接读写该区域
操作系统仅负责分配共享内存区并完成地址映射，不会自动提供同步保护，必须由用户程序引入同步互斥机制

#### 消息传递

操作系统提供了消息传递机制，可用于进程间通信。进程间的数据交换以格式化的消息为单位，通过OS提供的 **发送原语** 和 **接收原语** 进行。这种方式将通信的底层封装在内核，对用户透明
消息传递是应用最广泛的进程间通信机制，在微内核操作系统中，微内核与服务器之间的交互正是基于消息传递。此外，该机制很好地支持多处理器系统、分布式系统和计算机网络，因此也成为这些环境中的主流通信方式
消息传递由两种基本模式

- **直接通信方式** 发送进程通过发送原语将消息发送给指定的接收进程；内核负责将消息从发送方复制到接收方的内核缓冲队列中；接收进程通过接收原语接收消息
- **间接通信方式** 通信双发步直接指定对方，而是通过一个中间实体（通常称为信箱）进行消息交换。发送进程将消息投递到信箱，接收进程从信箱中取出消息

无论哪种方式，消息的投递均由OS内核完成

#### 管道通信

基于先进先出原则，常用于具有亲缘关系的进程（如父子进程）之间，以生产者-消费者模式进行数据交换
从编程接口上看，管道(pipe)表现为一种特殊的共享文件，支持read()和write()操作；从实现上看，它并非存储在磁盘上的文件，而是内核维护的一块大小固定的内核缓冲区
管道机制提供了3方面的协调能力：

1. 互斥：任一时刻只允许一个进程对管道进行读或写。但一个管道可以存在多个读进程和多个写进程
2. 同步：当管道满时，写进程自动阻塞，直到读进程取走部分数据；管道为空时，读进程自动阻塞，直到写进程向其中写入新数据
3. 写端关闭检测：当写端关闭后，读端read()返回0，表示无数据可读

在linux中，管道是一种广泛使用的IPC机制。主要特点：

1. 固定缓冲区大小
2. 自动阻塞与唤醒

管道由父进程通过pipe()系统调用创建。由于子进程在创建时会继承父进程的文件描述符表，因此能够通过这些描述符访问同一管道，从而与父进程进行通信
普通管道仅支持单向通信，若需要双向通信，则必须创建两个管道，分别用于两个方向的数据传输

#### 信号

信号，signal，是一种用于通知进程某个事件已经发生的机制。linux内核实现了约30种信号，编号通常为1-30
在进程的PCB种，用一个n位向量（linux使用一个32位整形变量）记录该进程当前待处理的信号。当向某进程发送一个信号时，内核会将该信号对应的位设置为1；一旦该信号被成功处理，对应位即被清零
此外，PCB还维护另一个n位向量，用于记录被阻塞（屏蔽）的信号。当某一位为1时，表示对应的信号不会被立即处理，而是暂存起来，直到解除阻塞
信号的发送主要由两种方式：

1. 内核发送信号。内核检测到特定的系统事件时，会向相关进程发哦是那个相应的信号。比如进程执行了非法指令，则内核发送SIGILL信号（序号为4）
2. 由进程发送信号。一个进程可以通过调用kill()函数，请求内核向指定进程发送信号。当然，也可以向自身发送信号

当OS由内核态返回用户态时，会检查当前进程是否存在未被阻塞的待处理信号。若存在，则立即处理其中一个信号（一般是处理序号较小的）
信号的处理方式有两种：

1. 执行默认的信号处理程序。操作系统为每类信号预设了默认操作，比如SIGILL信号的默认操作是终止进程
2. 执行进程自定义的信号处理程序。进程可以为某些（不是全部）信号定义自己的处理函数，比如收到SIGILL时输出hello world，而不是终止进程

### 2.1.7 线程和多线程模型

引入进程的目的是使多道程序能够并发执行，从而提高资源利用率和系统吞吐量；引入线程则是为了进一步降低程序并发执行时的时空开销，提升OS的并发性能
线程可被通俗地理解为“轻量级进程”，它是程序执行流的最小单元，也是处理器调度的基本单位。在多线程操作系统中，进程不再作为基本的执行实体，但仍保留与执行相关的状态
所谓进程处于“执行”状态，实际上是指该进程中的某个线程正在运行。线程的主要属性如下

1. 轻量级执行实体
   - 线程本身不具有独立的系统资源（如地址空间、打开的文件等），但拥有运行所需的私有数据结构，包括：线程id，PC，寄存器集合，栈。每个线程都有唯一的标识符和线程控制块TCB
2. 共享代码端
3. 资源共享
   - 同一进程内的所有线程共享该进程的代码段、数据段、堆、文件描述符等系统资源。这使得线程间的通信和数据共享很有效，无须IPC
4. 独立调度单位
   - 线程是CPU调度和执行的基本单位
5. 生命周期
   - 线程从创建开始，经历就绪、运行、阻塞等状态变化，直至最终终止

当线程切换发生在同一进程内部时，由于地址空间等资源无须切换，其开销远小于进程切换

#### 线程与进程的比较

1. 调度
   - 同一进程中，线程切换不会引起进程切换
2. 并发性
   - 同一进程内的多个线程可以并发执行
3. 拥有资源
   - 进程是资源分配的基本单位，而线程不拥有独立的系统资源，但拥有运行所需的私有数据结构
4. 独立性
   - 一个进程中的线程对其他进程完全不可见
5. 系统开销
   - 创建/撤销进程时，系统需分配或回收PCB、地址空间、IO资源等，开销显著；而创建或撤销线程仅需分配栈和少量内核对象，开销很小
   - 进程切换涉及整个地址空间和资源上下文的切换，而线程切换只需保存和恢复寄存器状态
6. 支持多处理器系统
   - 对于但线程进程，在任一时刻只能在一个CPU上执行；而对于多线程进程，系统可将其中的多个线程同时调度到多个CPU上并行执行

#### 线程的状态与生命周期

线程有三种基本状态：运行态、就绪态、阻塞态。其状态转换与进程类似
线程具有完整的生命周期。为了支持这些过程，OS提供了相应的系统调用或库函数
用户程序启动时，通常仅有一个初始线程在执行，其主要任务是创建其他线程。线程创建成功后，返回唯一的线程标识符
在大多数OS上，线程终止后并不会立即释放其占用的资源。只有当进程中的其他线程执行了相应的分离操作后，被终止的线程才会与资源分离，其资源才能被回收
已终止但尚未释放资源的线程仍可被其他线程调用，以使其重新恢复运行

#### 线程控制块

与进程类似，OS为每个线程维护一个线程控制块TCB。其通常包含：线程标识符、寄存器集合（PC、PSW、通用寄存器）、线程当前状态、调度优先级、线程局部存储区（用于保存线程私有的数据）、堆栈指针（指向该线程的私有栈）
同一进程内的所有线程共享该进程的地址空间和全局变量。每个线程拥有独立的私有栈，这些栈位于进程的地址空间内，因此从技术上将，一个线程可以访问另一个线程的栈内容。但这种做法严重违反编程规范

#### 线程的实现方式

线程的实现分两类：用户级线程和内核级线程（也称内核支持的线程）

##### 用户级线程

所有线程管理工作（包括创建、切换、撤销等）均由应用程序在用户空间（用户态）完成，无须OS介入，因此，内核完全感知不到这些线程的存在
应用程序只需引入线程库，即可被开发为多线程程序。调度仍以进程为单位进行

优点：

1. 线程切换在用户空间完成，无须切换到内核态，避免了模式切换的开销
2. 调度策略可有应用程序定制
3. 用户级线程的实现与OS无关，具有可移植性

缺点：

1. 系统调用的阻塞问题。当线程执行摸一个阻塞型系统调用时，整个进程会被挂起，导致进程中所有线程均被阻塞
2. 无法发挥多处理器的并行优势。内核仅将该进程调度到一个CPU上执行，即使系统配备了多个CPU核心，同一个进程中的多个线程也无法在不同CPU上并行运行

##### 内核级线程

内核级线程的管理完全由OS内核负责，所有线程相关的操作均在内核空间（内核态）完成。OS为每个线程维护了一个TCB，内核通过该TCB感知线程的存在并控制

优点：

1. 能发挥多处理器的有时
2. 阻塞处理更灵活。进程中的某线程因系统调用被阻塞，内核仍可调度该进程中的其他线程运行
3. 内核自身可采用多线程技术

缺点：

线程切换需要从用户态陷入到内核态

##### 组合方式

某些系统采用组合方式（混合模型）实现多线程。在该模式中，内核支持多个内核级线程的创建与调度，同时允许用户程序在用户空间管理多个用户级线程。有以下三种典型的多线程模型

1. 多对一模型
   - 将多个用户级线程映射到一个内核级线程。线程的调度和管理在用户空间完成。每个进程仅拥有一个内核级线程
2. 一对一模型
   - 将每个用户级线程映射到一个独立的内核级线程。进程中的用户级线程与内核级线程一一对应，线程的调度有内核完成，需要切换到内核态
3. 多对多模型
   - 将n个用户级线程映射到m个内核级线程，要求n>=m。用户级线程由应用程序在用户空间调度，而内核级线程由内核调度到多个CPU上执行

##### 线程库

程序员通常通过线程库提供的API来创建和管理线程。线程库的实现主要有两种方式：

1. 纯用户空间实现
   - 线程库完全位于用户空间，所有代码和数据结构均在用户态。调用库函数仅触发本地过程调用，无须陷入内核
2. 内核支持实现
   - 线程库的底层依赖操作系统内核。库中API的调用通常会触发系统调用，由内核完成实际的线程操作。此类实现对应内核级别线程模型

## 2.2 CPU调度

### 2.2.1 调度的概念

#### 1.调度的基本概念

CPU调度是指按照一定的算法（兼顾公平性与效率），从就绪队列中选择一个进程，并将CPU分配给它运行，从而实现多个进程的并发执行
CPU调度是多道程序操作系统的基础，也是操作系统设计的核心问题之一

#### 2.调度的层次

一个作业从提交到完成，通常要经历以下三级调度

##### (1)高级调度(作业调度)

高级调度负责从外存后背队列中按照一定规则挑选一个或多个作业，为其分配内存、IO设备等必要资源，并创建相应的进程，使其能够参与CPU竞争
简而言之，作业调度实现了内存与外存之间的调度
每个作业在整个生命周期中仅被调入一次、调出一次
传统 **多道批处理系统** 普遍配备作业调度；在分时或实时系统中，用户进程通常由交互式命令直接创建，一般不设置独立的作业调度模块

##### (2)中级调度(内存调度)

引入中级调度旨在提高内存利用率和系统吞吐量。当内存紧张时，它会将某些暂时无法运行的进程（比如阻塞态）**换出到外存**，此时进程的状态为 **挂起态**。此后，当这些进程具备运行条件且内存有空闲时，中级调度再将其换入内存，恢复为就绪态，并加入就绪队列等待调度。中级调度实际上是存储器管理中的 **对换功能**

##### (3)低级调度(进程调度)

低级调度按照特定算法从就绪队列中选择一个进程，将CPU分配给它。这是最基础、最频繁的一级调度，在所有OS中都必须存在。其调度频率很高，通常每几十毫秒执行一次

#### 3.三级调度的联系

在三级调度体系中，进程调度是最基本且不可或缺的，而作业调度和中级调度则选择性配置。三级调度协同工作，过程如下：

1. 作业调度为进程活动做准备，将作业调入内存并创建进程，使其具备参与调度的资格
2. 中级调度起调节作用，动态调节内存中活跃进程的数量
3. 进程调度驱动实际执行，是实现并发的核心机制
4. 调度频率依次提高：作业调度最低，内存调度次之，进程调度频率最高

### 2.2.2 进程调度

#### 1.进程调度任务

进程调度的任务主要包括：

##### 保存CPU现场信息

调度发生时，需要将当前进程的CPU状态(PC、通用寄存器)完整保存至其PCB中

##### 选取待运行进程

调度程序依据特定算法(如时间片轮转、优先级调度)，从就绪队列中选取一个进程，将其状态由“就绪态”改为“运行态”

##### 完成CPU分配

由分派程序将选中进程PCB中保存的CPU现场加载到处理器寄存器中，移交CPU控制权，使其从上次断点处恢复执行

#### 2.调度程序（调度器）

用于实现CPU调度与分派的软件组件称为 **调度程序**，它通常由三部分组成：

##### 排队器

将系统中所有就绪进程按策略组织成一个或多个就绪队列。每当有进程转换为就绪态时，排队器便将其插入相应的就绪队列

##### 分派器

根据调度算法选定的进程，分派器负责执行实际的CPU分配操作，任务包括：从就绪队列中移出目标进程、触发上下文切换、将CPU控制权转交给该进程

##### 上下文切换

在对CPU进行切换时，会发生两对上下文的切换操作：

- 第一对，将当前进程的上下文保存到其PCB中，再装入分派程序的上下文（cpu要运行分派程序，选择下一个进程）
- 第二对，移出分派程序的上下文，将新选进程的CPU现场信息装入CPU的各个相应寄存器

上下文切换需要执行大量load和store指令以保存寄存器内容，因此开销较大，目前通过硬件的方法减少上下文切换。通常采用两组寄存器，一组供内核使用，另一组供用户使用。这样，在上下文切换时只需要改变指针，使其指向当前所需的寄存器即可（这里说的是同一个进程的用户态和内核态切换。如果是不同的进程切换，还是要保存/恢复现场）

#### 3.调度的时机、切换与过程

调度程序是操作系统内核程序。在现代操作系统中，通常在以下情况下需要进行进程调度与切换：

1. 创建新进程后
2. 进程正常或异常终止后。若没有就绪进程，则通常运行一个系统提供的 **闲逛进程**
3. 进程因IO请求、信号量或其他原因而被阻塞时，必须调度其他进程运行
4. IO设备就绪后，发出IO中断，原先等待IO的进程由阻塞态变为就绪态

此外，在支持抢占的系统中，若更高优先级的进程进入就绪队列，也会触发调度并可能剥夺当前进程的CPU
切换通常紧随调度之后发生，其核心任务是保存原进程的执行现场，并恢复新进程的现场。具体而言，内核会将原进程的上下文（PC、PSW等）保存到PCB或内核栈中；随后从新进程的PCB或内核栈中加载上下文
然而，在以下情况中不能进行调度与切换：

1. 处理中断的过程中
2. 执行原子操作的过程中。如加锁、解锁、中断现场的保护与恢复等操作，通常需要屏蔽中断以保证原子性。在此期间，连中断都被禁止，更不应进行进程调度与切换

若在上述不可调度期间发生了调度条件，系统会设置一个 **调度请求标志**，等当前临界区域或中断处理完成后，再根据该标志执行相应的调度与切换操作

#### 4.进程调度的方式

所谓调度方式，是指当某个进程正在CPU上执行时，有优先级更高的进程进入就绪队列，此时系统应如何分配CPU。通常有两种进程调度方式：

##### 非抢占式调度方式

也称非剥夺方式，即使有优先级更高的进程进入就绪队列，系统仍让当前进程继续执行。

- 优点：实现简单、系统开销小，适用于早期的批处理系统
- 缺点：无法满足分时系统和大多数实时系统对及时响应的要求

##### 抢占调度方式

也称剥夺方式，有优先级更高的进程进入就绪队列时，调度程序可依据一定策略暂停当前进程，将CPU分配给更紧迫的进程
抢占调度方式对提高系统吞吐率和响应效率都有明显好处，但要遵循一定原则，如优先级、短进程优先和时间片原则等

#### 5.闲逛进程

当进程切换发生时，若系统中没有就绪进程，OS会调用闲逛进程（Idle Process）运行，它的PID=0。闲逛进程的优先级最低，仅在无其他就绪进程时运行

#### 6.两种线程的调度

1. 用户级线程调度。内核不知道线程的存在，因此调度仍以进程为单位
2. 内核级线程调度。内核直接感知并管理每个线程，调度时选择特定线程，而非进程。每个线程拥有独立的内核上下文，可被单独赋予时间片

### 2.2.3 调度的目标

不同的调度算法有不同的特性，以下为主要的指标：

#### CPU利用率

cpu利用率=cpu有效工作时间/(cpu有效工作时间+cpu空闲等待时间)

#### 系统吞吐量

单位时间内系统完成的作业数量。显然，短作业所需CPU时间较少，有助于提升吞吐量

#### 周转时间

指作业从提交到作业完成所经历的总时间，包括作业等待、在就绪队列中排队、在cpu上执行、IO操作等所有阶段的时间之和。即 周转时间=作业完成时间-作业提交时间
对于n个作业，则存在平均周转时间
带权周转时间用于衡量作业的相对等待程度，其定义为：带权周转时间=作业周转时间/作业实际运行时间

#### 等待时间

进程在就绪队列中等待CPU的总时间。调度算法并不影响执行时间和IO操作时间，仅影响等待时间，因此等待时间常被看作核心指标

#### 响应时间

指从用户提交请求到系统 **首次产生响应** 所经历的时间
不存在一种调度算法能同时满足所有用户需求和系统目标

### 2.2.4 进程切换

#### （1）上下文切换

将CPU切换到另一个进程，需保存当前进程的状态，并恢复另一个进程的状态。这个任务称为上下文切换。进程上下文由其PCB表示。切换流程如下：

1. 挂起当前进程，将其CPU上下文保存至PCB中
2. 将该进程的PCB移入相应的队列，如就绪队列或因等待某事件而进入的阻塞队列
3. 选择另一个进程执行，并更新其PCB中的相关信息
4. 恢复新进程的CPU上下文
5. 跳转到新进程PCB中的PC所指向的位置，开始执行该进程

#### （2）上下文切换的消耗

上下文切换是一项开销较大的操作，需要执行大量寄存器的保存与恢复指令。为减少这一开销，某些处理器架构提供多个寄存器组，通过切换寄存器组指针即可完成上下文切换。但大多数通用处理器仍需完整保存和恢复寄存器状态

#### （3）上下文切换与模式切换

模式切换（用户态和内核态之间的切换）与上下文切换是两个不同的概念。模式切换发生在同一进程内部。而上下文切换意味着从一个进程切换到另一个进程
上下文切换只能由内核完成，且整个切换过程运行在内核态
注意调度与切换的区别：调度是决策；切换是执行。通常由调度程序做出决策，随后触发上下文切换来执行该决策

### 2.2.5 CPU调度算法

#### 1.先来先服务（FCFS）调度算法

最简单的调度算法，可用于作业调度，也可用于进程调度
对于作业调度，每次选择最早进入队列的一个或多个作业；对于进程调度，每次从就绪队列中选择最早入队的进程，分配cpu，直到进程运行完成 **或阻塞**
属于非抢占式算法。特点是实现简单，但效率低。它对长作业有利，对短作业不利。有利于CPU密集型，不利于IO密集型

#### 2.短作业优先（SJF）调度算法

按照作业或进程的预计运行时间进行调度的策略
在作业调度中，SJF从后背作业中选择一个或多个估计运行时间最短的作业
在进程调度中，该策略称为短进程优先（SPF），即从就绪队列中选择估计运行时间最短的进程。缺点：

1. 对长作业不利，容易饿死
2. 未考虑作业的紧迫程度，完全忽略了作业的截至时间
3. 作业的运行时间是用户估计的

SPF既可以非抢占式（默认的），也可以是抢占式的。在抢占式版本中，若新进程到达就绪队列，若新进程的估计运行时间<当前进程的剩余时间，则分配给新进程。此时也称 **最短剩余时间优先** 调度算法
所有作业同时到达且运行时间已知时，SJF算法的平均等待时间和平均周转时间是最优的

#### 3.高响应比优先调度算法

主要用于作业调度，是对FCFS和SJF的一种综合平衡。每次进行作业调度时，系统首先计算后备作业队列中每个作业的响应比，选择最大的执行
响应比=(等待时间+估计运行时间)/估计运行时间
由公式可知：

- 等待时间相同时，运行时间越短，比值越大，因此有利于短作业
- 运行时间相同时，等待时间越长，比值越大，体现了公平性
- 对于长作业，等待时间变大，比值也会变大，避免了饿死

#### 4.优先级调度算法

为每个作业或进程分配一个优先级。在作业调度或进程调度中，每次选择优先级最高的
根据是否支持抢占，分为两类：
##### 非抢占式优先级调度算法

##### 抢占式优先级调度算法

根据进程创建后优先级是否可变，又可分为：

##### 静态

实现简单，开销小；但不灵活，可能导致低优先级进程饿死

##### 动态

进程创建时赋予一个初始优先级，但该优先级会动态调整，比如随等待时间的增加而提高。实际系统中，进程优先级设置遵循以下原则：

1. 系统进程>用户进程。系统进程负责管理核心资源和服务，通常被赋予更高优先级
2. 交互性进程>非交互性进程（或前台进程>后台进程）
3. IO型进程>计算型进程。IO型进程尽早获得CPU并启动IO操作，使IO设备尽早开始工作，进而提高系统整体吞吐量

#### 5.时间片轮转(RR)调度算法

该算法主要适用于分时系统，最大特点是公平性。系统将所有就绪进程按FCFS原则组织成一个就绪队列。每个固定的时间间隔（称为时间片，如30ms），系统产生一次时钟中断，激活调度程序，将CPU分配给就绪队列的队首进程，并允许其执行一个时间片。当进程执行完一个时间片，即使尚未运行完毕，也会被剥夺CPU，重新放入就绪队列的末尾
RR算法的调度时机：1.当前进程在时间片结束前已运行完成  2.时间片用尽，由中断处理程序触发调度程序
在该算法中，时间片的大小对系统性能由显著影响。若过大，大到让每个进程都能在一个时间片内完成，则退化称为FCFS；若过小，则会导致频繁的切换
在交互式系统中，常以“典型交互”作为参考基准。例如，用户在文本编辑器中输入一个字符，或在终端中按下回车键，这类操作通常只需几十到上百毫秒内即可完成。一个较为合理的时间片大小，应略大于一次典型交互所需的时间

#### 6.多级队列调度算法

该算法将系统中的就绪进程划分为多个独立的就绪队列，每个队列对应一类具有相似特性的进程。每个队列可独立采用适合其特性的调度算法。各个队列本身具有不同的优先级。在调度时，系统总是优先调度高优先级队列中的进程；只有当所有高优先级队列均为空时，才会调度低优先级队列中的进程

#### 7.多级反馈队列调度算法

该算法是时间片轮转调度算法与优先级调度算法的综合与发展。通过动态调整进程所处的队列（优先级）和对应的时间片大小，该算法能兼容多种目标：既有利于短进程，可提高吞吐量并缩短平均周转时间，又有利于IO进程以提升设备利用率和响应速度，且无须事先知道进程的运行时间。机制如下
1.设置多个就绪队列，每个队列赋予不同的优先级，第一级队列优先级最高，第二级次之。为各级队列分配不同的时间片，优先级越高的时间片越小。例如，i+1级通常是i级的2倍
2.每个队列内部采用时间片轮转（RR）调度。新进程创建后，首先被放入第一级队列的末尾。若时间片内未完成，则放入下一级队列的末尾。通常，最低优先级队列的时间片较长，其行为接近FCFS
3.按队列优先级调度。调度程序总是优先调度最高优先级队列中的进程执行。即第1至(i-1)级队列均为空时，才会调度第i级队列中的进程。此外，由于新进程总是先进入第一级队列，因此会抢占当前进程的cpu，将当前进程放入【原队列】末尾，并将cpu分配给新进程
该算法的优势体现在以下场景：
1.交互性（终端型）用户：进程通常较短且频繁进行IO
2.短批处理作业用户：优先级高，时间片小，可迅速执行完毕
3.长批处理作业用户：虽最终降低至低优先级，但在高优先级队列中能获得部分cpu时间，不至于饿死

#### 8.基于公平原则的调度算法

上述算法未将调度公平性作为主要设计目标。以下为以公平性为核心的调度算法
1.保证调度算法
为每个进程提供可量化的CPU时间分配保证。例如有n个并发进程，则每个进程应获得1/n的cpu时间
2.公平分享调度算法
保证调度算法对进程公平，但对用户不公平
公平分享调度算法则保证每个用户获得相同的CPU时间，或按所要求的比例分配

### 2.2.6 多处理机调度

根据处理机之间的协作方式，多处理机系统主要分为以下：
#### 1.非对称多处理机，AMP，通常采用主从式架构。一个主CPU负责全部调度决策和系统管理，其余CPU仅执行任务而不参与调度。内核一般运行在主CPU上，从CPU执行主CPU分配的进程
#### 2.对称多处理机，SMP，所有cpu地位对等，均可参与调度。调度程序可将任意就绪进程分配给任意空闲CPU
SMP的调度面临以下问题：
1）亲和性和负载平衡
当一个进程从一个cpu迁移到另一个cpu时，应将第一个cpu的缓存设置为无效，然后填充第二个cpu的缓存。这种操作代价较高，因此应尽量避免进程从一个cpu切换到另一个cpu，尽量让一个进程运行在同一个cpu上。这称为处理器亲和性
对于SMP系统，应尽量保证所有CPU的负载平衡（也称负载均衡）。但负载均衡通常会抵消处理器亲和性带来的好处。因此在某些系统中，只有当不平衡达到一定程度后，才会触发进程迁移
2）多处理机调度方案
方案一：公共就绪队列
系统中仅设置一个公共就绪队列，所有CPU共享该队列。cpu一旦空闲，就会从公共就绪队列中选择一个进程运行。优点是负载均衡，缺点是亲和性不好
有两种提升处理器亲和性的方法：
1.软亲和。指调度程序尽量将一个进程保持在某个cpu上，但这个进程也可能迁移到其他cpu上
2.硬亲和。指由用户进程通过系统调用，主动请求系统将其绑定到固定的CPU上。例如，linux实现了软亲和，也支持硬亲和的系统调用
方案二：私有就绪队列
系统为每个CPU设置一个私有就绪队列，当CPU空闲时，便从其对应的私有就绪队列中选择一个进程运行。该方案实现了处理器亲和性，但必须进行负载均衡。有两种办法实现负载均衡
1.推迁移。指指由一个特定的系统程序周期性地检查各CPU的负载，若发现不平衡，则从超载CPU的就绪队列中“推”处部分进程，迁移到空闲CPU的就绪队列中
2.拉迁移。指当某个CPU负载很低时，主动从超载CPU的就绪队列中“拉”取部分进程到自己的就绪队列
在实际系统中，推迁移和拉迁移常被结合使用
